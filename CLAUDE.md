# GBA WoW: notes for Claude

Private hobby GBA game (WoW-inspired open-world RPG), C++ with Butano. Milestones are in README.md;
the plan from level 20 to 60 (M12 to M26) is docs/level-60-roadmap.md.

## Build and check

- Submodule first: `git submodule update --init --depth 1` (Butano, pinned to a release tag).
- Build with Docker: `docker run --rm -v "$PWD":/src -w /src devkitpro/devkitarm make -j4`
  (in the cloud container, start the daemon with `sudo dockerd &` and prefix docker with sudo).
- Headless run + screenshots: `cc -O2 -o /tmp/mgba_script tools/headless/mgba_script.c -lmgba`
  (needs `libmgba-dev`), then e.g.
  `/tmp/mgba_script gba-wow.gba wait:30 hold:D:60 shot:/tmp/s.ppm` and look at the PPM.
- Always look at a screenshot after gameplay or art changes; CI uploads the same screenshots.

## Conventions

- Code: `gw_` file prefix, namespace `gw`, Butano style (snake_case, `_member` fields).
- No heap allocation in the game loop; use Butano containers and `bn::fixed`.
- World coordinates are pixels from the map's top-left; convert with `gw::world::to_screen_space`.
- Layers: ground BG priority 3, characters priority 2, overhead BG (tree tops, roofs) priority 1.
- Placeholder art is generated by `tools/gen_*.py`; edit the scripts, rerun them, commit the outputs.
- 4bpp backgrounds: every 8x8 tile must stay inside one 16-color bank and a background may use at
  most 1024 unique tiles; `worldgen.py` checks both when `gen_world.py` saves a map.
- Saves (`src/gw_save.cpp`) are chunks of tag, length and data, written field by field. A new field
  goes at the end of its chunk and a new list gets a new tag; old saves then load with defaults, so the
  save version only changes when a chunk's meaning does. Ids stored in saves (items, maps, quests,
  abilities, story flags, chest ids) are append-only. CI loads `tools/headless/saves/` and checks the
  result with `tools/headless/check_save.py`; keep those saves loading.
- Abilities (`src/gw_abilities.cpp`) list the levels of their ranks and the kits (subclasses) that get
  them; `rank_value` scales a rank with the level until the next rank. Talents are saved by their
  position in the subclass's tree, so reorder a tree only together with a save migration.
- A new ability needs a `default_bar` (Combat, Utility or Buffs) in `gw_abilities.cpp`; long buffs the
  hud should remind about go in `combat::missing_buff`.
- Bags are packed rows (`character().bags`, `bag_row_count()`): change them only through
  `add_item`, `remove_item` and `remove_from_row`, which keep them without gaps. Lists of the bags
  for the player go through `bag_view` (sorted, with headings).
- Menus and the HUD share the UI layer (BG priority 0); HUD icons are sprites at priority 1 so text
  can sit on top of them.
- Enemy abilities are data: `src/gw_enemy_abilities.cpp` is the shared table (ids append-only) and an
  `enemy_def` names its family, AI style and up to two of them. `src/gw_enemy_ai.cpp` runs them for
  every enemy in a fight (casts, strikes, charges, fleeing, calls for help) and puts debuffs on the
  player; elites' scripted moves stay in `combat::boss_update`. A new debuff goes at the end of
  `buff_id` (`gw_buffs.h`) with an icon in `buff_icons` (`gw_hud.cpp`).
